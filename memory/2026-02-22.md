### Pipeline Improvements Committed Today

**Planner Agent** (ADR-012 pattern: triage-then-plan)
- Architect sets `complexity_hint: high/low` + structural triggers (network, secrets, polling, ≥2 string inputs)
- Planner runs between Architect and Engineer for complex specs
- Produces 5-section plan: validation, threat model, API sequence, edge cases, WASM guidance
- All 3 agents (Architect, Planner, Engineer) now know the continue-signal pattern

**Continue-Signal Pattern** (documented in design doc)
- WASM tools never block indefinitely — ≤60s execution budget
- Return `status: pending` + resume token when time expires
- Caller owns retry loop, backoff, overall deadline
- Architect designs interface with optional `message_id` input + `status` output from the start

**Architect INPUT SPECIFICATION RULES** (mechanical checklist per field)
- Every string: max length + regex/charset
- Every number: min AND max, both "inclusive" stated explicitly
- URL-bound fields: strict allowlist regex + explicit rejection
- Credential fields: exact header, CRLF strip, never-in-errors rule, generic error text only
- Resume tokens: same format validation + existence check note
- Optional fields: exact behavior absent vs present both specified

**Bug Ticket Severity Tiers**
- Critical/High: blocking (trigger fix loop, circuit breaker)
- Medium/Low: advisory (reported in artifact, don't block)
- Social engineering / verbatim text display = Medium (not High)
- CRLF injection in HTTP headers = Critical (must fix)

**Circuit Breaker Escalation Policy**
- `on_circuit_breaker = proceed | ask | fail` in girt.toml
- Currently: `proceed` (fail open, bootstrap mode)
- `ask` (future): routes through approval WASM, gives human: summary + Architecture + QA verdict + RedTeam verdict as separate attachments
- `max_iterations = 3` (was 5)

**Per-Stage Timing + Token Tracking**

### 🎉 discord_approval WASM HTTP fixed — end-to-end approval flow working!

**Root cause of stub HTTP** resolved: `discord_approval@0.1.0` was built against old DEFAULT_WIT
(missing WASI HTTP imports). New build uses `wasm32-wasip2` target + `wit-bindgen::generate!`.

**WIT dependency resolution fix** (critical lesson learned):
- `cargo-component` can't resolve `wasi:http` without internet (pkg.registry.wasm.pub unreachable)
- Switched to `wasm32-wasip2` target + `wit-bindgen::generate!` with local WIT files
- WIT deps must be in **subdirectories** (not single bundled files) matching multi-file packages
- `wasi:http/types.wit` and `handler.wit` have no `package` header — must prepend `package wasi:http@0.2.6;`
- `wasi:clocks`, `wasi:io` from `wasmtime-wasi-http-36.0.5/wit/deps/` already have proper headers
- Compiled to 207KB valid component; `wasm-tools validate --features component-model` passes
- Export is `run: func(input: string) -> result<string, string>` — matches girt-runtime `get_func("run")`

**`impl Guest for Component`** (not `impl exports::girt::tool::run::Guest`) — how wit-bindgen generates it

**Manual WIT deps setup for future builds**:
```
wit/
  world.wit                  ← package girt:tool; world girt-tool { import wasi:http/...; export run; }
  deps/
    clocks/                  ← copy from wasmtime-wasi-http-36.0.5/wit/deps/clocks/
    io/                      ← copy from wasmtime-wasi-http-36.0.5/wit/deps/io/
    http/
      types.wit              ← prepend "package wasi:http@0.2.6;" then cat types.wit
      handler.wit            ← prepend "package wasi:http@0.2.6;" then cat handler.wit
```
