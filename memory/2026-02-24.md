### VAD / End-of-Speech Detection
- webrtcvad silence detection never triggers — background farm noise keeps `is_speech=True`
- RMS energy gate added (threshold=300) but insufficient — Discord sends continuous packets when its own VAD thinks user is speaking
- **Key insight**: Discord only sends audio packets when it thinks user is transmitting. When user stops, packets stop.
- **Solution: Packet gap detector** — background thread checks every 250ms if no audio packets received for 1.0s, auto-flushes utterance
- Results: ~2s overhead without muting vs instant with mute. No-mute path: ~5s total, mute path: ~3s total

## Late Session pt2 — Debounce Timer Rewrite (10:10-10:28pm)

### Major Refactor: Replaced VAD+gap checker with debounce timer
- **Deleted**: webrtcvad processing in VoiceSink, RMS energy gate, packet gap background thread, `start_gap_checker()`
- **Added**: Simple resettable 250ms debounce timer per user
- Every audio packet resets the timer via `call_soon_threadsafe` → `_schedule_flush`
- When packets stop for 250ms, `_debounce_flush` fires and emits accumulated PCM
- Mute button still works as instant flush via `flush_user()` method
- Thread safety: `write()` (audio thread) schedules all timer ops on event loop

### Append+Cancel in Dispatcher
- New speech arriving before TTS starts playing cancels in-flight pipeline
- Audio is accumulated in `user_audio` dict across utterances
- Cancelled task's audio gets combined with new speech, pipeline restarts with full audio
- On successful TTS playback, accumulated audio clears

### Whisper Hallucination Problem
- 250ms debounce triggers on tiny noise fragments → Whisper hallucinates "Thank you", "Bye", etc.
- This caused a loop: phantom "Thank you" → LLM "You're welcome!" → repeat
- **Fix 1**: MIN_UTTERANCE_MS = 800 — discard audio under 800ms before STT
- **Fix 2**: Hallucination filter in voice_pipeline.py — rejects known phantom phrases (set of ~20 common hallucinations)

### Bug Fixes
- `NameError: SAMPLE_RATE` — needed to import from vad.py
- Thread safety: timer cancel from audio thread was unsafe — moved all timer ops to event loop via `call_soon_threadsafe`

### Known Issue
- Duplicate responses: cancelled tasks sometimes complete if they were past the cancellation checkpoint (LLM done, about to TTS). Need finer-grained cancellation checks.

### Key Learnings from Live Testing
- **Gateway auth**: Must use `client.id="gateway-client"`, `client.mode="backend"`, Ed25519 device signing
- **Gateway agent routing**: Must pass `agentId: "main"` or get "Pass --to" error
- **Streaming text is cumulative**: Each `event:agent` frame has full text so far, not deltas
- **Qwen3-8B tool calling unreliable**: Sometimes says "let me check with Bel" as text without calling tool — need fallback detection
- **Escalation as fire-and-forget task**: Must survive pipeline cancellation from new speech
- **Farm noise**: Constant "Thank you" hallucinations from background noise, need energy gate
